# FitTrack — notes for Claude Code

Private, mobile-first fitness PWA for 2–5 invited users. Spec: `FitTrack_Claude_Code_Build_Spec.md`.
Progress checklist: `docs/implementation-plan.md` (keep it updated as phases land).

## Hard rules

- **No nutrition features.** No calories, macros, nutrition labels, recipes, food database, barcode scanning.
  Meals are named, scheduled reminders with an optional description/notes only.
- **No AI dependency in V1.**
- Never ship secrets to the client: the browser only gets `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`,
  `VITE_VAPID_PUBLIC_KEY`. Service-role key and VAPID private key live only in Edge Function secrets.
- Every user-owned table: RLS enabled, policies `to authenticated` with `(select auth.uid()) = user_id`,
  UPDATE policies with both `using` and `with check`, explicit column-level grants, nothing for `anon`.
- New SQL functions get `set search_path = ''`; revoke EXECUTE from `public, anon, authenticated` and grant back
  only what clients must call. SECURITY DEFINER only when unavoidable, and it must check `auth.uid()` itself.
- Store canonical metric units (kg, cm, ml, m, seconds); convert only for display (`src/lib/units.ts`).
- Timestamps are `timestamptz` (UTC). Schedules use local `time` + the user's IANA timezone (`profiles.timezone`).
- Notifications are opt-in, respect quiet hours, and are idempotent via unique occurrence keys.

## Stack

React 19 + TS + Vite 8, Mantine 9 (no Tailwind), React Router 8 (data router), TanStack Query 5, Zustand 5,
Mantine Form + Zod 4 (`schemaResolver(schema, { sync: true })`), Recharts 3, Dexie 4, vite-plugin-pwa
(injectManifest, `src/sw.ts`), React Three Fiber/Drei (lazy), Vitest 5 + RTL + Playwright, Supabase.

## Layout

```
src/
  app/            providers, theme, router, query client
  components/     shared UI (AppLayout bottom nav, PageHeader, SectionCard, StatusIndicator…)
  features/<x>/   feature modules: api.ts (queries/mutations), pages and components
  lib/            supabase client + unwrap, env (zod), units, time (dayjs tz), platform
  offline/        Dexie database + outbound sync queue (Phase 2)
  stores/         small Zustand stores (sync status, workout activity)
  types/database.ts  generated by Supabase — regenerate after migrations
  sw.ts           service worker (precache, push handlers)
supabase/migrations/   SQL migrations (source of truth; also applied to the hosted project)
supabase/functions/    Deno Edge Functions (`_shared/` helpers)
tests/db/         PGlite-based migration + RLS tests (no Docker)
e2e/              Playwright specs
```

## Commands (Node 22: `nvm use`)

- `npm run dev` — Vite on http://localhost:3000 (matches Supabase's default Site URL)
- `npm run verify` — typecheck + lint + format check + all tests + build
- `npm run test:unit` / `npm run test:db` — Vitest projects
- `npm run check:functions` — `deno check` Edge Functions
- `npm run generate:icons` — PWA icons from `public/favicon.svg`

## Conventions

- Query hooks live in `features/<x>/api.ts`; wrap Supabase calls with `unwrap()` so errors throw.
- Use `useUserId()` inside authenticated routes; `usePreferences()` for units + timezone.
- Client-generated UUIDs (`crypto.randomUUID()`) for anything created offline; writes are idempotent upserts.
- Keep components small, feature-oriented; no premature abstraction (2–5 users).
- Tests: unit tests next to code (`*.test.ts[x]`), DB/RLS tests in `tests/db`.

## Testing

- `npm run verify` before calling anything done (typecheck, lint, format, unit + PGlite DB tests, build).
- `npm run test:e2e` with `E2E_*` env (see README) for browser flows. Axe scans fail on serious/critical issues.
- Local smoke scripts live in `scripts/.*.mjs` and `scripts/smoke-*.mjs`. They are gitignored because they use
  test credentials.

## Supabase

- Hosted project ref `scihuwuayemelfzziuqu`. Migrations are applied with the Supabase MCP `apply_migration`.
  Large payloads, `DROP` and `DELETE … USING` need interactive approval, so split migrations and avoid those
  statements. The local files are canonical; remote history uses split names.
- Regenerate types with MCP `generate_typescript_types`; when the result is saved to a file, run
  `python3 scripts/write-types.py <saved-result.json>`.
- Server secrets (VAPID, cron) live in Vault via `public.app_secret` / `set_app_secret` (service role only).
- Auth: invite-only. First account becomes admin (DB trigger). Admin invites via the `admin-invitations`
  Edge Function, which returns a one-time `/auth/confirm?token_hash=…&type=invite` link (email optional).
